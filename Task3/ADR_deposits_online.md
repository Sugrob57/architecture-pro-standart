Комментарии к диаграмме:
1. Для реализации интеграции Интернет-банка c Kafka потребуется обновление платформы
2. В АБС добавлен модуль "Ставки". Планируется что данные в него будут заливать сотрудники бекофиса. Событие о появлении новых ставок публикуется в Kafka, чтобы их мог забрать Интернет-банк
3. Заявки из интернет-банка не будут напрямую добавляться в АБС. Вместо этого в АБС они попадут асинхронно, при обработке событий в Kafka 
4. Для сайта будет использоваться тот же самый Backend, что и для интернет-банка - это позволит упростить архитектуру клиентских приложений и сократить количество шифрованных каналов интеграции. 
5. Интеграцию сайта с смс-шлюзом тоже можно сделать через Backend интернет-банка. Прямая стрелка отображена для понимания интеграций
6. Так как в базе данных нет критичиски важных данных - только предрасчитанные и справочные, актуальную информацию в БД можно подливать по событиям из Kafka - при необходимости сразу в обе базы - в основной ЦОД, и в резервнй.
7. Backend интернет-банка можно реализовать (на .NET последней LTS версии - у команды есть экспертиза по данной технологии, и интеграция с Frontend'ом будет только через REST API.

### **Альтернативы**
1. Вариант прямой интеграции интернет-банка с АБС отклонен, из-за риска превысить допустимую нагрузку на БД АБС
2. Вариант прямой интеграции сайта с АБС отклонен, из-за риска превысить допустимую нагрузку на БД АБС
3. Расмотрен вариант оставить процесс работы со ставками через Excel, без изменений. Отклонен - т.к. придется загружать ставки в несколько систем

**Недостатки, ограничения, риски**

1. Появляется новая система - Kafka. Будут издержки по ее поддержке.
2. Не раскрыт вопрос интеграции Kafka и АБС, возможно на текущем стеке (Delphi) интеграция будет затруднена.
3. Не раскрыт вопрос реализации новых СМС-нотификаций в СМС-шлюзе. Есть риск что внутренняя команда не сможет реализовать данную доработку.
4. Не раскрыт вопрос автоматического переключения интернет-банка с основного ЦОД на резервный и обратно
