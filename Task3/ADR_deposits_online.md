Комментарии к диаграмме:
1. Для реализации интеграции Интернет-банка c Kafka потребуется обновление платформы.
2. В АБС добавлен модуль "Ставки". Планируется что данные в него будут заливать сотрудники бекофиса. 
3. Потребуется добавить небольшой микросервис "EventsProcessor" для интеграции с Kafka, расширяющий возможности АБС (пока что с минимальным функционалом). Сервис может быть реализован на Java - т.к. у команды АБС есть экспертиза в этом языке.
4. Событие о появлении новых ставок публикуется в Kafka, чтобы их мог забрать Интернет-банк.
5. Заявки из интернет-банка не будут напрямую добавляться в АБС. Вместо этого в АБС они попадут асинхронно, при обработке событий в Kafka. 
6. Для сайта будет использоваться тот же самый Backend, что и для интернет-банка - это позволит упростить архитектуру клиентских приложений и сократить количество шифрованных каналов интеграции. 
7. Интеграцию сайта с смс-шлюзом тоже можно сделать через Backend интернет-банка. Прямая стрелка на диаграмме контейнеров отображена для понимания интеграций.
8. Так как в базе данных нет критичиски важных данных - только предрасчитанные и справочные, актуальную информацию в БД можно подливать по событиям из Kafka - при необходимости сразу в обе базы - в основной ЦОД, и в резервнй.
9. Backend интернет-банка можно реализовать на .NET последней LTS версии - у команды есть экспертиза по данной технологии, и интеграция с Frontend'ом будет только через REST API.

### **Альтернативы**
1. Вариант прямой интеграции интернет-банка с АБС отклонен, из-за риска превысить допустимую нагрузку на БД АБС.
2. Вариант прямой интеграции сайта с АБС отклонен, из-за риска превысить допустимую нагрузку на БД АБС.
3. Расмотрен вариант оставить процесс работы со ставками через Excel, без изменений. Отклонен - т.к. придется загружать ставки в несколько систем.
4. Рассмотрен вариант реализовать интеграцию с Kafka в текущей системе АБС. Отклонен из-за сложности реализации на языке, который используется в системе (Delphi).

**Недостатки, ограничения, риски**

1. Появляется новая система - Kafka. Будут издержки по ее поддержке.
2. Не раскрыт вопрос реализации новых СМС-нотификаций в СМС-шлюзе. Есть риск что внутренняя команда не сможет реализовать данную доработку и потребуется привлечение вендора.
4. Не раскрыт вопрос автоматического переключения интернет-банка с основного ЦОД на резервный и обратно. Обеспечение балансировки ендпоинтов сайта и интернет-банка требует отдельного ADR.
