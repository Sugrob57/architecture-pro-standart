### **Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| F1 | Клиент, Сотрудник кол-центра | Получение справочной информации по депозитам по телефону | 1.Клиент звонит в кол-центр банка<br/> 2.Клиент интересуется ставками по депозитам<br/> 3.Сотрудник кол-центра просматривает актуальные данные по депозитам в системе кол-центра и консультирует клиента|
| F2 | Клиент, Сотрудник партнерского кол-центра | Получение справочной информации по депозитам по телефону через партнерский кол-центр | 1.Клиент звонит в партнерский кол-центр<br/> 2.Клиент интересуется ставками по депозитам<br/> 3.Сотрудник кол-центра просматривает актуальные данные по депозитам в своей системе и консультирует клиента |

Событие о появлении новых ставок уже публикуется в Kafka. На данном этапе требуется:
1. Добавить Kafka Consumer в CRM кол-центра - забирать актуальные ставки при их появлении.
2. Доработать модуль АБС, который публикует события в Kafka - добавить в него публикацию ставок еще и в файловое хранилище партнера.

### **Альтернативы**
1. Вариант развертывания отдельного сервиса для публикация файлов в партнерский кол-центр отклонен - т.к. доработка минимальна, и может быть реализована в существующих сервисах.
2. Прямая интеграция между CRM и АБС уже имеется, но использоваться здесь будет только для получения данных по ставкам, но не для мониторинга их появления/обновления - чтобы не повышать нагрузку на АБС.

**Недостатки, ограничения, риски**
1. Недостаточно информации, как публиковать файлы в партнерский колл-центр, следует уточнить формат передачи данных. Можно предложить публикацию в облако, в файловое хранилище партнера (текущий отраженный вариант), или автоматическую отправку файла по email.
2. Интеграция Kafka и CRM должна пройти без проблем - платформа на Java легко может быть интегрирована, но потенциально потребуется привлечение команды подрядчика CRM.
