| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | **Функциональные (Functionality)**     |              |
| F1  | На сайте новый клиент видит список доступных депозитов с актуальными ставками |              |
| F2  | Клиент может подать заявку на открытие депозита   |              |
| F3  | Клиент видит персонализированные ставки депозитов лично для него в интернет-банке  |              |
| F4  | Клиент может подать заявку на открытие депозита по персональным условиям в интернет-банке   |              |
| F5  | Сотрудники как бэк-офиса депозитов, так и бэк-офиса кредитов должны иметь возможность работать с данными ставок    |  Стоит реализовать в АБС            |
| F6  | Клиент должен получить СМС-уведомления после подтверждения размера ставки и открытия депозита     |              |
| F7  | На сайте новый клиент видит предложение открыть кредит по некоторой ставке    |              |
| F8  | Клиент может подать заявку на кредит на сайте. Операцию необходимо будет подтвердить с помощью СМС-кода  |              |
| F9  | Если клиент ещё заполнит паспортные данные, он должен сразу получить решение об одобрении или неодобрении ему кредита  |              |
| F10 | В интернет-банке клиент видит список доступных кредитов с актуальными условиями так же, как и на сайте  |              |
| F11 | Клиенту может выводиться предодобренное предложение по кредиту  |              |
| F12 | Клиент информируется по СМС об изменении статуса заявки на кредит  |              |
| F13 | Заявки на кредит по предодобренным предложениям должны обрабатываться сотрудниками в течение того же рабочего дня  |              |
| U   | **Удобство использования (Usability)** |              |
| U1  | Интерфейс работы должен быть максимально удобным для клиента                               |              |
| U2  | Нужно придерживаться системы дизайна для приложений, которая принята в компании. Пользователи при работе должны видеть привычные цвета и брендированные элементы                                |              |
| R   | **Надёжность (Reliability)**          |              |
| R1  | Данные с сайта необходимо защищать с помощью механизма шифрования трафика.    |              |
| R2  | В интернет-банке данные при передаче также надо защитить механизмом шифрования    |              |
| R3  | Сайт и интернет-банк должны работать 24/7 и быть доступны в 99,9% случаев   |              |
| R4  |  Система кредитного скоринга не должна выполнять процессы по предрасчетам скорингов в рабочее время   |              |
| R5  | Онлайн-подача заявок не должна напрямую интегрироваться с АБС, т.к. база данных АБС системы уже перегружена. Расширение количества продуктов может поставить под угрозу работоспособность банка   |  Нужна асинхронная интеграция с АБС. Подойдет Kafka |
| P   | **Производительность (Performance)**   |              |
| P1  | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды. Сейчас справочные данные загружаются дольше секунды | Стоит добавить новую БД для интернет банка (и сайта)  |
| P2  | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку. Нужно поддержать резервирование через второй ЦОД   |              |
| P3  | Заявки на кредит по предодобренным предложениям будут обрабатываться сотрудниками в течение того же рабочего дня - Сейчас это сделать невозможно, АБС не выдержит |    |
| P4  | Нужно избежать прямой работы интернет-банка с API АБС в процессе кредитования  |              |
|  P5 | Нужна периодическая синхронизация между BPM и АБС  |  Стоит реализовать публикацию событий из АБС в Kafka. Это позволит быстрее принимать решения по кредитным заявкам в BPM  |
| S   | **Поддерживаемость (Supportability)**  |              |
| S1  | Cтавки по депозитам сейчас не ведутся нигде, кроме XLS-файлов. Добавить интеграцию с АБС |  |
| S2  | Можно попробовать микросервисную архитектуру для интернет-банка депозитов  |              |
| S3  | Для очереди сообщений стоит использовать Kafka   |              |
| S4  | Стоит использовать базы данных MS SQL и Oracle - Уже используются в банке  |   |
| +R  | **+ Ограничения (Restrictions)**      |              |
| +R1  | Функционал работы с СМС реализован в ядре системы. Он требует доработки со стороны подрядчика, но этого лучше избежать. Реализовать такой бизнес-функционал можно силами команды разработки банка  |              |
| +R2  | Текущая версия интернет банка несовместима с Kafka - Требуется обновление    |   |
| +R3  | Нужно предусмотреть разработку документации для дальнейшего расширения системы  |              |
| +R4  | АБС может масштабироваться только вертикально, из-за своей базы данных.  |              |
